# User workflow preferences

- Whenever changes are made for a requested task, complete relevant validation, commit the task changes, and push directly to GitHub before reporting completion. The user has authorized this workflow; do not leave completed work only in the local checkout.
- Include any database schema changes and migrations necessary to complete the request. Apply them through the project's established workflow when required; report any access or execution blockers clearly.
- Preserve unrelated work and never force-push or discard remote changes to publish a task.
